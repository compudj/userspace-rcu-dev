Fractal Trie design: bit selection combinations

Mathieu Desnoyers
October 3, 2025

* Note: After analysis of the generated populations (fractal-trie-testpop), it
  appears that aiming for a single cache line hit per node would degrade
  the functional density (minimizing how many cache lines are required
  to fit a number of items). On 64-bit, with 1024 node size, a
  16-subclasses split with sub-classes of size 7 can only fit 79 items
  populations (at 99% success rate). Compared to this, a 4-subclasses
  split with sub-classes of size 28 can fit 101 items populations
  (99% success rate). A 2-subclasses split with sub-classes of size
  56 (sill a single cache line scan on 64-bit) can fit 105 items
  populations (at 99% success rate).

  Therefore, the approach discussed below will not be implemented.

This is an extension to the Fractal Trie design with the following goals:

- Guarantee that only a single cache line is loaded per internal node
  level (the prior Fractal Trie implementation has internal nodes that
  require hitting two cache lines),
- Use combination bit selection to minimize the number of bits needed to
  represent the split of up-to-256-values populations into multiple
  sub-classes (2 to 16).
- Adapt to modern 64-bit architectures (2025) which have 64 bytes cache lines.

* Combinations

We can calculate the number of combinations for bit selection over
8-bit as selector to split the node population.

The number of combinations of r = { 2, 3, 4 } items within n=8 items:

* 32-bit architectures (optimizing for 64 bytes cache lines, common for 2025 hardware)

Note: Older hardware with 32 byte cache lines will hit two cache lines per node in some
node representations. Our main target is 32-bit compatibility binaries running on current
hardware (2025).

We need 3 bits to represent the 8 node configurations.
We want to encode the node configuration and the sub-classes selection in
the low-order bits (LSB).

* Computing the best N bits selection to balance 2^N sub-classes:

- Find the bits with highest entropy (split closest to 50% `0` and 50% `1`).
- For a population of values P.
- Count bit frequencies: For each bit position (n=0-7), count how many times they
  are `1` (nr_bit1[n]) across P.
- Note: our goal is to maximize the Shannon Entropy, but let's rely on something
  simpler to calculate with integers: minimize the distance to (nr_elem(P) / 2).
- For each bit position (n=0-7), calculate the distance D between nr_bit1[n]
  and (nr_elem(P) / 2).
- Select the best bits: sort the bits by calculated distance D[n].
- Pick the N bits with the lowest distance D[n].

* AI Queries

Used Gemini 2.5 Flash, Gemini 2.5 Pro, GPT-5, Sonnet-4.5 with the following query:

You are an expert programmer 
I have random number populations including numbers from zero to 255 
Those numbers are represented as 8 bit integers 
I want to split those populations into four classes. Those classes are selected to keep the number of items per class as balanced as possible. The selection is done by choosing four bits from the values as selector.
How can I efficiently compute the best choice of bits for any given population of numbers? 

Gemini 2.5 Flash, GPT-5, and Sonnet-4.5 all recommend a brute-force approach.
E.g. for 4 bit selection from 8 bits, the complexity is O(N + 256 * 70).

Gemini 2.5 Pro has a different, interesting approach based on calculating the
entropy of each bit, and select the bits with most entropy.
